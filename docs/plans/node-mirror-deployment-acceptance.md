# 节点镜像外部出口与部署验收

承接 [镜像代码计划](./node-mirror-site-proxy.md) 中不能由受控 HTTP/TLS/WS 单测证明的外部端到端与发布事项。全部为未来待验收，本轮没有生产部署授权；不添加功能，不扩大可代理地址，不开放 PUBLIC。

## 授权与验收清单

- [ ] A1：由维护者明确环境、维护窗口、目标版本/提交、参与节点、观察周期及执行人，先使用隔离部署；涉及生产再单独取得授权，不读取或外传真实密钥。
- [ ] A2（原端到端 1）：使用受控出口观测站点分别从两个实际节点访问，留存脱敏请求关联与观察结果，证明出口随指定节点变化，Master 不代为直连。
- [ ] A3（原端到端 2 / Raw/API/Release 结果）：验证真实 GitHub Raw、API、Release 下载、HEAD、Range 续传及内容哈希/状态；记录站点限制和测试时刻，不预设外站必然可用。
- [ ] A4（原端到端 3）：实际 Release 重定向仅访问允许域名，最终请求仍经指定节点，越界/降级被拒绝；记录最终 host，不保存含敏感参数的完整 URL。
- [ ] A5（原端到端 4）：确认部署说明与用户可见行为未承诺完整 GitHub 网页、Cookie 会话或内链重写，记录未支持行为而非伪造“完整镜像”成功。
- [ ] A6（原运维 1）：取得授权后执行双库/WAL/SHM 与运行资源的停服备份、哈希/密钥校验和隔离恢复演练，确认恢复路径；生产备份内容不入仓库。
- [ ] A7（原运维 2）：按审核版本先部署/迁移 Master，再滚动升级 Agent 并核对 WSS、HTTPS 入口与反向代理流式配置；记录实际版本与能力。
- [ ] A8（原运维 3）：在实际部署中验证离线、HTTP 轮询和未宣告 `mirror_proxy` 的旧 Agent 不承载任务；已有单测不能替代环境配置验证。
- [ ] A9（原运维 4）：默认保持 PUBLIC 关闭，先用 ADMIN/短期 SHARE 验证，明确生产权限及限额后再逐站开放；记录授权，不能因计划存在自行启用。
- [ ] A10（原运维 5）：在约定窗口采集请求数、成功率、状态、耗时、字节、取消/超限、断线及并发占用，验证配置的上限和清理；记录采样完整性与观察时间，不给无测量的绿灯。
- [ ] A11（原运维 6）：验证禁用或轮换分享 Token 后新访问被拒绝、活动流结束，滥用处置不放宽任意 URL/地址白名单，记录审计与资源回收。
- [ ] A12（原运维 7 / 灰度回滚）：演练关闭镜像入口、恢复已审核代码/数据的回滚流程，活动请求失败且不被新版进程错误恢复；记录结果和遗留问题。

## 证据与归档条件

每项至少记录提交/产物版本、环境、执行时刻、步骤、观察值与成功/失败结论；同一请求关联信息必须脱敏，禁止保存 Token、Cookie、Authorization、数据库内容或完整秘密 URL。失败要保留可复现摘要。

目前无 A1—A12 的本轮环境结果。代码计划的 66 项定向通过只作为启动前检查，不能用于勾选本表。全部实际验收完成后，才由主代理/维护者运行 `pnpm plan:archive node-mirror-deployment-acceptance.md`；本轮只创建承接计划，不归档。
